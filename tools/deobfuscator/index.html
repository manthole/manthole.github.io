      Comment ça marche ?
      

      Un script malveillant est souvent empilé de couches : une ligne powershell -enc contient du Base64, qui contient un script compressé, qui contient lui-même du texte découpé en morceaux. L'outil applique des règles de transformation en boucle, en retirant une couche à chaque passage, jusqu'à ce que plus rien ne change. Chaque étape est affichée, pour comprendre le chemin.
      

      Couches reconnues : -EncodedCommand (y compris ses abréviations et les tirets typographiques), Base64 de [Convert]::FromBase64String et atob, compression Deflate et Gzip, codes [char] et String.fromCharCode, concaténations, opérateur de format -f, .Replace et -replace, chaînes inversées, tableaux joints, accents graves (I`E`X) et circonflexes de cmd (p^o^w^e^r^s^h^e^l^l), échappements \x41 et %u0041, code passé à IEX ou eval, variables constantes.
      

      Limites
      

      Ce n'est pas un émulateur : les obfuscations calculées à l'exécution (XOR, boucles, tableaux de type _0x4f2a[…]) ne sont pas résolues. Pour aller plus loin, CyberChef, ou des outils qui exécutent le script de façon contrôlée, comme box-js, uniquement dans une machine virtuelle isolée. Le bon réflexe en SOC ne change pas : on ne lance jamais un script suspect « pour voir ».
      

      

      

      How does it work?
      

      A malicious script is often stacked in layers: a powershell -enc line holds Base64, which holds a compressed script, which itself holds text split into pieces. The tool applies transformation rules in a loop, removing one layer per pass, until nothing changes. Every step is shown, so you can follow the path.
      

      Recognised layers: -EncodedCommand (including abbreviations and typographic dashes), Base64 from [Convert]::FromBase64String and atob, Deflate and Gzip compression, [char] and String.fromCharCode codes, concatenations, the -f format operator, .Replace and -replace, reversed strings, joined arrays, backticks (I`E`X) and cmd carets (p^o^w^e^r^s^h^e^l^l), \x41 and %u0041 escapes, code passed to IEX or eval, constant variables.
      

      Limits
      

      This is not an emulator: obfuscation computed at run time (XOR, loops, _0x4f2a[…]-style arrays) is not resolved. To go further, use CyberChef, or tools that run the script in a controlled way, such as box-js, only inside an isolated virtual machine. The SOC rule stays the same: never run a suspicious script "just to see".
      

      

      

      ¿Cómo funciona?
      

      Un script malicioso suele estar apilado en capas: una línea powershell -enc contiene Base64, que contiene un script comprimido, que a su vez contiene texto troceado. La herramienta aplica reglas de transformación en bucle, quitando una capa en cada pasada, hasta que nada cambia. Cada etapa se muestra, para entender el camino.
      

      Capas reconocidas: -EncodedCommand (incluidas sus abreviaturas y los guiones tipográficos), Base64 de [Convert]::FromBase64String y atob, compresión Deflate y Gzip, códigos [char] y String.fromCharCode, concatenaciones, operador de formato -f, .Replace y -replace, cadenas invertidas, arrays unidos, acentos graves (I`E`X) y circunflejos de cmd (p^o^w^e^r^s^h^e^l^l), escapes \x41 y %u0041, código pasado a IEX o eval, variables constantes.
      

      Límites
      

      No es un emulador: las ofuscaciones calculadas en tiempo de ejecución (XOR, bucles, arrays del tipo _0x4f2a[…]) no se resuelven. Para ir más lejos, CyberChef, o herramientas que ejecutan el script de forma controlada, como box-js, únicamente en una máquina virtual aislada. El buen reflejo en un SOC no cambia: nunca se lanza un script sospechoso «para ver».
      

      

      

      Como funciona?
      

      Um script malicioso é muitas vezes empilhado em camadas: uma linha powershell -enc contém Base64, que contém um script comprimido, que por sua vez contém texto cortado em pedaços. A ferramenta aplica regras de transformação em ciclo, removendo uma camada a cada passagem, até nada mudar. Cada etapa é mostrada, para compreender o caminho.
      

      Camadas reconhecidas: -EncodedCommand (incluindo as suas abreviaturas e os travessões tipográficos), Base64 de [Convert]::FromBase64String e atob, compressão Deflate e Gzip, códigos [char] e String.fromCharCode, concatenações, operador de formato -f, .Replace e -replace, cadeias invertidas, arrays unidos, acentos graves (I`E`X) e acentos circunflexos do cmd (p^o^w^e^r^s^h^e^l^l), escapes \x41 e %u0041, código passado a IEX ou eval, variáveis constantes.
      

      Limites
      

      Não é um emulador: as ofuscações calculadas em tempo de execução (XOR, ciclos, arrays do tipo _0x4f2a[…]) não são resolvidas. Para ir mais longe, CyberChef, ou ferramentas que executam o script de forma controlada, como o box-js, apenas numa máquina virtual isolada. O bom reflexo num SOC não muda: nunca se executa um script suspeito «para ver».
      

      

      

      Wie funktioniert es?
      

      Ein bösartiges Skript besteht oft aus gestapelten Schichten: Eine Zeile powershell -enc enthält Base64, das ein komprimiertes Skript enthält, das wiederum in Stücke zerlegten Text enthält. Das Tool wendet Transformationsregeln in einer Schleife an und entfernt bei jedem Durchlauf eine Schicht, bis sich nichts mehr ändert. Jeder Schritt wird angezeigt, damit du den Weg nachvollziehen kannst.
      

      Erkannte Schichten: -EncodedCommand (einschließlich Abkürzungen und typografischer Gedankenstriche), Base64 aus [Convert]::FromBase64String und atob, Deflate- und Gzip-Kompression, Codes [char] und String.fromCharCode, Verkettungen, Formatoperator -f, .Replace und -replace, umgekehrte Zeichenketten, zusammengefügte Arrays, Backticks (I`E`X) und cmd-Zirkumflexe (p^o^w^e^r^s^h^e^l^l), Escapes \x41 und %u0041, an IEX oder eval übergebener Code, konstante Variablen.
      

      Grenzen
      

      Das ist kein Emulator: Zur Laufzeit berechnete Verschleierungen (XOR, Schleifen, Arrays wie _0x4f2a[…]) werden nicht aufgelöst. Wer weiter gehen will: CyberChef oder Tools, die das Skript kontrolliert ausführen, wie box-js – ausschließlich in einer isolierten virtuellen Maschine. Der richtige SOC-Reflex bleibt: Ein verdächtiges Skript startet man nie „nur mal zum Schauen“.
